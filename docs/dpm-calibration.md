# DPM 신호 세기 보정 — 문헌 근거와 적용 내용

DPM 신호 지도가 실측보다 신호를 과하게 좋게 보여 주던 문제를, **우리 측정에 값을 맞추지 않고** 논문·표준의
값으로 보완한 기록이다. (2026-10-15)

## 1. 문제

한림리츠빌(`hanl.wifisettings`) 실측 8지점과 비교한 기존 모델의 오차 (예측 − 실측):

| 밴드 | 편향 | MAE |
|---|---|---|
| 5 GHz | +7.6 dB | 7.6 dB |
| 2.4 GHz | +15.1 dB | 15.1 dB |

- 공유기에서 2.7 m, 가시선(LOS)인 **거실 지점에서도 2.4 GHz 가 +18 dB** 틀렸다. 이 거리에서는 경로 손실 지수·벽
  손실이 거의 영향을 주지 않으므로, 오차의 대부분은 경로 손실 모델 밖(링크 버짓)에 있다.
- 실측은 5 GHz 가 2.4 GHz 보다 오히려 5 dB 강했다(물리적으로는 자유공간 손실이 6.7 dB 더 커야 함).
  기존 앱은 80 MHz 채널에 "대역폭 보정" 6 dB 를 빼고 있었고, 이것이 5 GHz 의 과대 예측을 가려 왔다.

## 2. 저장된 DPM 논문에서 확인한 것

| 논문 | 확인 내용 |
|---|---|
| Wölfle et al., *Dominant Path Prediction Model for Indoor Scenarios*, GeMiC 2005 | 경로 손실 지수 p 는 전파 상태(LOS / OLOS / NLOS)마다 다르게 둔다. 실내는 도시보다 크게. 모델은 측정으로 교정하는 것을 전제 |
| Wölfle & Landstorfer, *Dominant paths for the field strength prediction*, VTC 1998 | 경험 모델 L = L_FS + L_T + **L_O**, "오프셋 L_O 는 교정에 쓴다" |
| Wölfle et al., *Extensions to the field strength prediction technique…*, EPMCC 1997 | 가시성(LOS/OLOS/NLOS)·도파로·수신 위치 주변 효과를 별도 파라미터로 다룸 |
| Plets et al., EURASIP JWCN 2012:123 | n = 2, PL₀ = 40 dB @1 m 고정. 측정한 것은 안테나를 뺀 **경로 손실**. 90% 음영 여유 5.4~8.2 dB |
| Khrouf et al., PIMRC 2008 | 수신 전력 = P_e + G_e + **G_r** − L (Eq. 7). 수신 안테나 이득·급전선 손실이 링크 버짓에 들어감 |

→ 저장된 논문의 경로 손실 식은 이 앱과 일치한다. 빠진 것은 **(1) 전파 상태별 지수, (2) 수신 쪽 링크 버짓 항**이며,
저장된 논문에는 두 값의 구체적 수치가 없어 추가 조사했다.

## 3. 추가 조사

| 출처 | 값 |

| Adame, Carrascosa, Bellalta, *The TMB path loss model for 5 GHz indoor WiFi scenarios*, arXiv:1812.00667 (2018) | 상용 공유기(TP-Link Archer C7)·상용 단말 실측: LOS 구간 **L₀ = 54.12 dB @1 m**, γ = 2.06, 벽당 5.25 dB. 20/40/80 MHz 의 RSSI 에 **유의한 차이 없음**(각주 11) |
| IEEE 802.11ax (TGax) 주거 경로 손실 모델 (위 논문 Eq. 1 에 인용) | 5 m 까지 n = 2, 이후 3.5, 벽당 5 dB |
| 스마트폰 안테나 효율 벤치마크 (TU/e), 5 GHz 손 효과 연구 | 단말 안테나 총효율 약 −6~−8 dB, 손에 의한 추가 손실 최대 −5.85 dB (참고용) |

## 4. 적용한 변경

1. **대역폭 보정 제거** (`LinkBudget`) — RSSI 는 채널 폭에 따라 줄지 않는다(TMB 실측). 넓은 채널은 SNR 에만 영향.
2. **전파 상태별 경로 손실 지수** (`DpmPathGrid`) — WinProp "가구 있는 건물" 값 LOS 2.1 / OLOS 2.3 / NLOS 2.5.
   자유공간(n = 2)을 넘는 몫 10·(p − 2)·log₁₀(l) 을 물리 경로 손실에만 더한다(경로 선택에는 미반영).
   - 상태 판정은 지배 경로 기준(WinProp 정의가 공개돼 있지 않아 이 앱의 해석):
     꺾임 없음 + 벽 없음 = LOS, 꺾임 없음 + 벽 관통 = OLOS, 꺾임 있음 = NLOS.
     "꺾임 없음" = 누적 방향전환 손실 < 0.5 dB (열린 공간 22.5° 한 번 미만, 격자 지그재그 수준).
3. **수신 장비 손실 7.39 dB** (`LinkBudget.RECEIVER_LOSS_DB`) — TMB 의 L₀(54.12 dB) − FSPL(1 m, 5.18 GHz)(46.73 dB).
   Khrouf 2008 Eq. 7 의 수신 쪽 항(G_r, 실장 손실)에 해당하는 상용 장비 실측값.

최종 식:

```
RSSI = (송신 출력 + 안테나 이득) − PL_DPM − 7.39
PL_DPM = FSPL(l) + 10·(p−2)·log₁₀(l) + Σ벽 손실 + Σ방향전환 손실 − 도파로 이득   (p = 2.1 / 2.3 / 2.5)
```

## 5. 결과 (실측 8지점, 값을 맞추지 않음)

| 밴드 | 변경 전 편향 / MAE | 변경 후 편향 / MAE | 변경 후 표준편차 |
|---|---|---|---|
| 5 GHz | +7.6 / 7.6 dB | **+3.2 / 6.0 dB** | 6.6 dB |
| 2.4 GHz | +15.1 / 15.1 dB | **+4.6 / 7.3 dB** | 7.5 dB |

단계별 기여(편향, 5 GHz / 2.4 GHz): 대역폭 보정 제거 +13.6 / +15.1 → 상태별 지수 +10.4 / +12.0 → 장비 손실 +3.0 / +4.6.
남은 표준편차(6~7 dB)는 Plets 2012 의 음영 여유(5.4~8.2 dB) 수준이다.

## 6. 한계

- 비교 지점은 한 집의 8곳뿐이다. 다른 집·다른 단말로 검증하지 않았다.
- 장비 손실 7.39 dB 는 5 GHz·노트북 수신 실측에서 나온 값이고, 2.4 GHz 와 스마트폰에 같은 값을 쓰는 것은 가정이다.
  실측 공유기의 실제 송신 출력(앱은 17 dBm + 5 dBi 가정)도 확인되지 않았다.
- 오차가 큰 지점(오른쪽위 침실 5 GHz +13.8, 현관·오른쪽위 침실 2.4 GHz +12~14 dB)은 벽·꺾임 손실 쪽 문제일 수 있다.
- FDTD 정밀 검증의 절대값 문제는 아래 8절에서 고쳤다.

## 7. 회귀 테스트

모델을 의도적으로 바꿨으므로 골든 격자(`./gradlew goldenDump`), 신호 지도 픽셀 해시, 공유기 자리 추천 기준값을
다시 만들었다. 이후 리팩터링에서는 이 값이 유지돼야 한다.

## 8. FDTD 정밀 검증 — 절대 신호 세기 (2026-10-15 추가)

공유기 자리 추천 "정밀" 모드의 FDTD 검증에 두 가지 문제가 있었다.

1. **좌표 변환 오류** — 도면 좌표를 `px / cellPx + pml` 로 격자에 옮겼지만, 실제 격자 칸 크기(dx)는 파장 기준으로
   정해져 `cellPx` 와 다르다(예: 한림 도면 5 GHz 에서 약 6.5배). 측정점·공유기 둘레 모두 엉뚱한 칸을 읽고 있었다.
2. **상대값** — 공유기 옆 전력을 0 dB 로 둔 뒤 EIRP 를 더해, 기준 거리까지의 손실이 빠지고 2D 파동의 1/r 감쇠만
   반영돼(3D 는 1/r²) 절대 세기가 수십 dB 후했다.

고친 방식 (`engine/FdtdPathLoss`): 자유공간 몫은 3D 해석식, 벽·회절·반사로 생기는 추가 손실만 FDTD 에서 얻는다.

```
PL(x) = FSPL(r, f) + 10·log10(P_ref / P(x)) − 10·log10(r / r_ref)
  P_ref : 공유기 둘레 1 m 원 위 전력의 중앙값 (그 거리까지는 자유공간)
  P(x)  : x 둘레 반 파장 이내 격자 전력 평균 (간섭 무늬 완화)
  마지막 항 : 2D 원통파가 자유공간에서 이미 겪는 감쇠를 빼서 "추가" 손실만 남긴다
RSSI = LinkBudget.rssiDbm(라디오, PL)   ← 신호 지도와 같은 링크 버짓
```

검증:
- 벽 없는 빈 공간에서 FSPL 과 ±3 dB 이내 (`FdtdPathLossTest`)
- 한림 실측 8지점 (정밀 검증과 같은 6000 스텝):

| 밴드 | 예전 방식 편향 / MAE | 새 방식 편향 / MAE | (참고) DPM |
|---|---|---|---|
| 5 GHz | +39.9 / 41.7 dB | **+4.6 / 5.4 dB** | +3.2 / 6.0 |
| 2.4 GHz | +40.3 / 40.3 dB | **+6.8 / 7.2 dB** | +4.6 / 7.3 |

한계:
- 실시간 표시용 격자 상한(45만 칸) 때문에 집 한 채 크기에서는 칸이 커져 소스 주파수가 약 1.4 GHz 로 깎인다.
  주파수를 깎지 않는 해상도(5 GHz 약 670만 칸)로도 돌려 봤지만 정확도가 나아지지 않았고(5 GHz MAE 6.9,
  2.4 GHz 9.1 dB) 5 GHz 한 번에 102 초가 걸려 그대로 두었다.
- 여러 공유기를 한 번에 시뮬레이션하므로 각 지점은 가장 가까운 공유기를 지배 송신원으로 본다(근사).

### 피드백 루프 결함 (검증을 고치자 드러남)

예전 검증은 늘 수십 dB 후하게 나와 "커버율 부족 → 공유기 위치 조정" 피드백이 사실상 돌지 않았다.
검증을 고치자 피드백이 실제로 돌면서 두 가지 결함이 드러나 함께 고쳤다.

1. 모든 공유기를 **전체** 약한 지점의 중심으로 끌어당겨 공유기들이 한곳에 모였다
   (한림 도면 2대: 그리디 위치 3.4 m 간격 → 조정 후 0.8 m). → 약한 지점을 가장 가까운 공유기에 나눠 맡긴다.
2. 옮긴 결과가 더 나빠도 마지막 배치를 그대로 냈다. → 검증한 배치 중 가장 좋은 것(커버율, 같으면 균일도)을 남긴다.

한림 도면, 건물 안쪽 전체 선택, 공유기 2대, 목표 −65 dBm, 5 GHz 정밀 모드:

| | 위치 (px) | FDTD 검증 커버율 |
|---|---|---|
| 그리디만 | (560,440), (440,360) | — |
| 예전 피드백 | (560,440), (547,408) — 0.8 m 간격으로 모임 | 80.1% |
| 고친 피드백 | (560,440), (321,345) — 약했던 왼쪽 방들 쪽으로 | **82.5%** |

## 9. 실측에 쓴 공유기 — LG U+ GAPD-7500R

- GAPD-7500R 은 GAPD-7500 의 안테나 분리형으로 칩셋이 다르다(Realtek RTL8198D). 송신 출력·안테나 이득은
  공개 자료(뉴스, 커뮤니티, 인증 목록)에서 찾지 못했다.
- GAPD-7500(일반형)은 2차 자료 기준 안테나 이득 2.4 GHz 5 dBi / 5 GHz 6 dBi — 앱의 `LGU_WIFI6` 프리셋
  (송신 20 dBm 가정)이 이 값이다.
- 이 프리셋 값을 실측 프로젝트에 넣으면 EIRP 가 3~4 dB 커져 DPM 편향이 5 GHz +7.2 dB, 2.4 GHz +7.6 dB 로
  오히려 커진다. 실제 방사 전력이 사양 최대치보다 낮게 설정돼 있거나(송신 출력 조절), 스마트폰 수신 손실이 TMB 의
  노트북 기준 7.39 dB 보다 크다는 뜻일 수 있지만, 기준 수신기 없이 둘을 구분할 수는 없다.
- 그래서 모델 값은 바꾸지 않았다. 정확한 송신 출력(공유기 관리 페이지의 송신 출력 설정, 제품 사양서)을 알게 되면
  측정 프로젝트의 공유기 설정만 바꿔 다시 비교하면 된다.
